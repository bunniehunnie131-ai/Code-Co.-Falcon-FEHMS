ForteDB project database package

Files
- ForteDB_Schema.sql: creates the database tables used across account, catalogue, cart, booking, fulfilment, payments, returns, reviews, and contact workflows.
- ForteDB_Product_Seed_Colours.sql: the supplied 182-product seed with the detailed colour values.
- ForteDB_Complete_Setup.sql: the schema followed by the colour product seed in one runnable script.
- Web.config.connectionStrings.xml.txt: connection strings for the SQL Server instance specified in the project.
- Login.aspx.cs: replacement for the current hard-coded login code-behind; it checks the registered PBKDF2 password hash in dbo.Users.

Target database and app connection
The product seed files use USE ForteDB, and the project's Catalogue.aspx.cs and Registration.aspx.cs request the connection string named ForteDB. This package therefore targets a database named ForteDB. Replace the current <connectionStrings> block in Web.config with the entries in Web.config.connectionStrings.xml.txt; both names point at the same ForteDB database because different existing pages use each name.

Run setup
1. Open ForteDB_Complete_Setup.sql in SQL Server Management Studio.
2. Review the target server/database, then execute it. It creates missing tables and seeds or updates the 182 products by ImageUrl. It does not delete products or other rows.
3. Ensure the project's Images folder contains the image files referenced by the seed script.
4. Replace Presentation/Login.aspx.cs with the included Login.aspx.cs so sign-in checks the registered user in dbo.Users rather than the current hard-coded email/password values.

The script is safe to rerun for the schema and the product seed. The supplied product scripts contain the same product set; the colour version has the more detailed colours, so run the combined setup or the colour version, not both seed variants in sequence. Running the other variant later would change those colour values back to "Various".

How the schema maps to the current pages
- Registration.aspx.cs inserts into dbo.Users and dbo.Customer. The Users insert trigger fills the split-name/email/role fields needed by the existing Manage Customers code.
- Login.aspx.cs verifies the PBKDF2 hash already generated by RegistrationSecurityService, records UserID/UserEmail/UserRole in Session, then redirects customers or staff.
- Catalogue.aspx.cs reads dbo.Product using ProductID, ProductName, Description, Category, Colour, Price, QuantityAvailable, ImageUrl, and IsAvailable.
- Cart and checkout pages currently carry the cart and form values in ASP.NET Session. Carts and CartItems are included for later persistence if you choose to connect them.
- The Booking, BookingItems, BookingServiceProviders, Payments, BookingTasks, and return tables are ready for order and operations persistence. The existing checkout/payment/confirmation code currently uses Session and does not yet insert those records into these tables; that requires additional code-behind changes.

Security notes
- The schema stores the existing encrypted ID number as VARBINARY(MAX) and the PBKDF2 password hash; it contains no plain-text password column.
- Payments stores only a payment reference, bank name, and last four digits. Never store the full card number or CVV.
- New customer rows created by the existing Manage Customers page have a NULL PasswordHash; those accounts need a password setup/invitation flow before they can sign in.
